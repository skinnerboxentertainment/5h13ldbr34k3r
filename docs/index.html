How it works

  1. Recover the mapping from the font. The browser needs ShieldFont's full substitution table to render decoys, so the table ships inside the font. Reading the font's GSUB ligature rules, the composite glyph outlines, and the character map reproduces every pair — {decoy_word → original_word}.
  2. The mapping is an involution. For every pair, m[m[x]] === x, so decoding is re-encoding. This page applies the same transform both ways.
  3. Decode the HTML. Tokenize text runs, look up each word case-preservingly, apply the context-aware digit rule (1568→1073 but M15-EN untouched). Structure, scripts, and code are preserved.

The mapping shown here was derived from optik-a.woff2 by prototype/source/shieldguard.py — the same tool, in Python, that decodes whole pages. No dictionary was copied from the upstream repo.
